01 — 信号の流れ

空気の震えが数字になるまで

まず全体像。マイクからの音は、5つの箱を通って2種類のデータになる。

Web Audio API は、音の処理を「ノード」という箱をつないで組み立てる。AS1 が使う経路はとてもシンプルで、マイク → AudioContext → AnalyserNode の一本道だ。最後の AnalyserNode が、音を解析用の数字に変換してくれる。

ここで大事なのは、AnalyserNode が同じ音を2つの見方で渡してくること。この「2つの見方」＝時間領域と周波数領域が、以降すべての土台になる。

02 — 2つの見方

時間領域と周波数領域

同じ音を「波」で見るか「成分」で見るか。用途がまるで違う。

時間領域は、空気の圧力が時々刻々どう揺れたかの生の波形。ここからは「今どれくらい大きい音か」＝音量が取れる。周波数領域は、その波を「どの高さの音がどれだけ混ざっているか」に分解したもの。FFT（高速フーリエ変換）という計算で得られ、声の“形”はほぼここに現れる。

音量（音圧・dB）はどこから来るか

波形の各サンプルを二乗して平均し、平方根を取る（RMS）。それを対数に直すと dB になる。AS1 は「静けさ＝0dB」に見えるよう、実際の値からノイズフロアを引いてオフセットしている。

rms = √(Σ x² / N) → 20·log₁₀(rms) — ambient-score.html:2724

スペクトルの「ビン」と「卓越周波数」

FFT はスペクトルを細かい区画（ビン）に区切って返す。1ビンの幅は ナイキスト周波数 ÷ ビン数。ナイキスト周波数はサンプリングレートの半分で、「測れる上限の高さ」を意味する。もっともエネルギーが強いビンの周波数が卓越周波数——その瞬間いちばん目立つ音の高さだ。

FFTサイズを上げるとビンが細かくなり、周波数の分解能が上がる（代わりに1フレームに必要な時間が延びる）。AS1 の FFT 2048 などの選択肢は、この「細かさ ↔ 反応の速さ」のトレードオフを切り替えている。
03 — 4つの手がかり

声を見分ける、4つの特徴量

「人の声らしさ」を1つの数字で決めず、性質の違う4つの指標を重み付きで足す。

空調やファンの音も、会話も、同じ「音」だ。決め手は声だけが持つ構造にある。AS1 は次の4つを 0〜1 で測り、重みを掛けて合算する。定常的な機械音に強い（＝ピッチ・倍音）指標を厚くしているのが v2.7.1 以降の設計。

42%フォルマント隆起formantElevationScore
25%ピッチdetectPitch · 自己相関
18%倍音構造harmonicScore
15%声帯域エネルギー比voiceBandRatio

① フォルマント隆起 — 声道が作る“こぶ”

人ののどと口（声道）は共鳴管として働き、特定の帯域を持ち上げる。この山をフォルマントと呼ぶ。声では中域（500〜3000Hz）が高域（3000〜8000Hz）よりはっきり盛り上がる。広帯域ノイズは高い方へなだらかに下がるだけなので、この“こぶ”が出にくい。

② ピッチ — 声には「高さ」がある

母音には基本周波数（声の高さ、およそ80〜300Hz）がある。AS1 は波形の自己相関で高さを測る。波を少しずつずらして自分自身と掛け合わせ、いちばんよく重なるズレ幅（周期 T）を探す。高さ = サンプリングレート ÷ T。よく重なるほど「明瞭度」が高く、声らしい。定常的な機械音は明確な周期を持たないので、ここが伸びない。

③ 倍音構造 — 声は“櫛”の形をしている

有声音は基本周波数 f0 の整数倍（2f0, 3f0, …）にエネルギーが並ぶ。ピークとピークのあいだは谷になる。この山と谷の交互＝櫛（くし）の歯のような構造は、声や楽器に特有で、ブロードバンドノイズにはほとんど無い。AS1 は倍音の位置（k倍）と中間（k+0.5倍）を比べ、その差（dB）を得点化する。

④ 声帯域エネルギー比 — どこに力が集まっているか

最後はいちばん素朴な指標。全体のエネルギーのうち、声の主戦場（200〜3000Hz）に何割集まっているか。空調やファンは低域（数十〜200Hz）に力が偏るので、この比率が低い。声が入ると中域の比率が上がる。単体では弱いが、他の3つを補強する“地力”の指標だ。

voiceEnergy(200–3000Hz) ÷ totalEnergy — ambient-score.html:2146
04 — 合成と門番

4つを1つの判定にまとめる

重み付き合算 → 周波数ゲート → 活動ゲート。3段で誤検知を抑える。

4指標を重みで足して voiceScore を作り、そこに2つの「門番（ゲート）」を掛ける。門番は、声らしさが揃っていても状況的にありえないケースを弾く役割だ。

なぜ2つのゲートが要るのか。 定常的なファンや空調は、スペクトルの“形”だけ見ると偶然フォルマントらしく見えることがある。だが「背景よりぐっと大きい」「200Hz以上に力がある」という状況条件までは満たしにくい。ゲートは、形の判定をくぐり抜けた偽陽性を、文脈で最後に落とす仕組み。v2.7.1 でファン誤検知を抑えたのは、主にこの重み配分とゲートのしきい値を戻したことによる。
