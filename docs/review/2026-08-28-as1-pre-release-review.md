## 目的

## Findings

### P1: メモ欄の入力がDOM XSSになる

対象:
- `ambient-score.html:3574`
- `ambient-score.html:3584`

`sendMemo()` で、ユーザー入力 `text` を `innerHTML` に直接差し込んでいる。

```js
entry.innerHTML = `
  <span class="log-time">${formatClock()}</span>
  <span class="log-val-voice" style="color:#aaccff;">📝 ${text}</span>
`;
```

このため、メモ欄に以下のような文字列を入力すると、HTMLとして解釈され得る。

```html
<img src=x onerror=alert(1)>
```

`addLogEntry()` やレポート生成側では `escHtml()` が使われているため、ここだけ防御が抜けている。

推奨修正:
- できれば DOM を `createElement()` で組み立て、ユーザー入力は `textContent` で設定する。
- 最小修正なら `${escHtml(text)}` に置き換える。

受け入れ条件:
- メモ欄に `<img src=x onerror=alert(1)>` を入力しても、文字列として表示されること。
- レポート出力側のエスケープ挙動を壊さないこと。
- 手動ラベルの表示は従来どおり動作すること。

### P1: 「声の占有率」が仕様どおり「測定時間中の割合」になっていない

対象:
- `ambient-score.html:3070`
- `ambient-score.html:3155`
- `README.md:131`
- `ambient-score.html` UI文言: 「測定時間中に声があった割合」

README/UIでは、声の占有率を「測定時間中に声があった割合」と説明している。

しかし実装では、`totalFrameCount++` が活動ゲートを通過した後の分岐内でのみ実行される。

```js
if (dbShifted < 2 || activityDb < 6) {
  ...
} else {
  ...
  totalFrameCount++;
  if (isVoice) {
    voiceFrameCount++;
    ...
  }
}
```

そのため、静寂や背景音のみの時間は分母に含まれない。結果として、長い静寂の中に短い発話があるケースでは、実時間ベースより声の占有率が高く出る。

静粛スコアにも直接影響するため、公開前に仕様と実装を揃える必要がある。

推奨修正:
- 公開向けには README/UI の説明どおり、「測定時間中の割合」に揃える。
- `totalFrameCount` は測定中の評価フレーム全体の分母として増やす。
- 静寂/背景音ゲート中も、声ではないフレームとして分母に含める。
- `voiceFrameCount` は `isVoice` のときだけ増やす。

注意:
- 現仕様を維持する選択肢もあるが、その場合は README/UI を「活動音中の声割合」のように変更する必要がある。
- 今回の公開用途では、ユーザーが直感的に理解しやすい「測定時間中の割合」への修正を推奨する。

受け入れ条件:
- ほぼ静寂の測定時間が長く続いた場合、その時間が占有率の分母に含まれること。
- 声のイベント数のカウントが不自然に増えないこと。
- 静粛スコアが新しい分母定義に基づいて再計算されること。
- ファン誤検知対策 v2.7.1 の挙動をできるだけ崩さないこと。

### P2: CSVのテキストエスケープが不完全

対象:
- `ambient-score.html:3511`
- `ambient-score.html:3526`
- `ambient-score.html:3493`
- `ambient-score.html:3648`
- `ambient-score.html:4161`

現在の `csvSafe()` はCSVインジェクション対策のみを部分的に行っているが、CSVセルとしてのエスケープが不足している。

主な問題:
- 値内の `"` を `""` に変換していない。
- メモに改行が含まれる場合の扱いが明確でない。
- 先頭に空白・タブ・改行があり、その後に `=`, `+`, `-`, `@` が来るケースを防げない。
- サマリーCSV/履歴CSV側は共通エスケープを通っていない。

推奨修正:
- CSVセル用の共通関数を作る。
- テキスト値は以下を一貫して処理する。
  - CSV式インジェクション対策
  - ダブルクォートのエスケープ
  - 必要に応じたセル全体のクォート
  - 改行の保持または空白化
- ログCSV、リアルタイムファイルログ、サマリーCSV、履歴CSVで同じ関数を使う。

受け入れ条件:
- メモに `a,b`、`a"b`、`=1+1`、` @SUM(A1:A2)` のような文字列を入れてもCSV列が崩れず、Excel等で式として実行されないこと。
- 数値列の出力形式は従来どおり扱いやすいままであること。

### P2: READMEの「平均音量=算術平均」と実装がズレている

対象:
- `README.md:84`
- `ambient-score.html:2742`

READMEでは平均音量を「測定開始からの算術平均」と説明している。

一方で実装は、dB値を線形エネルギーへ戻して累積し、最後にdBへ戻している。

```js
sessionSum += Math.pow(10, dbShifted / 10);
const sessionAvg = sessionCount > 0 ? 10 * Math.log10(sessionSum / sessionCount) : 0;
```

音圧レベルの平均としては実装の方が自然なので、コードではなく README 側の文言を直すのがよい。

推奨修正:
- README の「算術平均」を「エネルギー平均」または「音圧レベルをエネルギー換算して平均」に変更する。
- UIツールチップにも同様の表現が残っていれば合わせる。

受け入れ条件:
- README と UI の説明が、実装の平均計算方法と矛盾しないこと。

### P3: アプリ画面の更新日がREADMEと不一致

対象:
- `ambient-score.html:1554`
- `README.md:6`

READMEは以下。

```text
v2.7.1 ｜ 更新日: 2026-08-28
```

アプリ画面は以下。

```html
v2.7.1 | 更新日：2026-07-08
```

公開配布物として信頼感に関わるため、日付を揃えること。

推奨修正:
- `ambient-score.html` の画面表示を `2026-08-28` に変更する。

受け入れ条件:
- README、画面表示、必要なら配布zip内のファイルが同じバージョン/更新日を示すこと。
